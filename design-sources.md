# Design Reference Sources

Before drafting slide layouts and visual structure (Step 3 of SKILL.md), fetch and skim these sources. Use whatever web fetch/search capability is available in the current environment. If a site can't be reached (blocked, paywalled, changed URL), note that to the user and fall back to general best-practice knowledge rather than stalling the workflow.

## Curated sources

1. **Garr Reynolds — Presentation Zen design tips**
   https://www.garrreynolds.com/design-tips
   Look for: simplicity/minimalism principles, the "signal vs. noise" idea, use of empty space, image-led slides over bullet-heavy slides, story-driven structure.

2. **Microsoft PowerPoint — Design Ideas blog**
   https://powerpoint.cloud.microsoft/create/en/blog/powerpoint-design-ideas/
   Look for: practical layout patterns, how Designer-style auto-layouts think about slide composition, current PowerPoint-native design conventions.

3. **Microsoft PowerPoint — Best creative presentation ideas, topics, layouts and designs**
   https://powerpoint.cloud.microsoft/create/en/blog/the-best-creative-presentation-ideas-topics-layouts-and-designs/
   Look for: creative layout variety (not just bullet-and-title), topic-specific formatting ideas, ways to keep a deck visually varied across sections.

4. **Microsoft Support — Tips for creating and delivering an effective presentation**
   https://support.microsoft.com/en-US/PowerPoint/tips-for-creating-and-delivering-an-effective-presentation
   Look for: baseline mechanical best practices (text density limits, font size minimums, consistent templates, rehearsal/delivery tips worth mentioning to the user even though delivery isn't something Claude builds).

5. **EDUCAUSE Presenter Concierge — Resources**
   https://www.educause.edu/conferences-events/presenter-concierge/resources
   Look for: academic/conference-oriented presentation guidance — useful when the deck is for a school, research, or academic-competition context (relevant given many users of this skill are building competition or school decks).

## How to use these

- Skim, don't transcribe. Pull out 3-5 concrete principles that are actually relevant to the deck being built (e.g. a technical pitch deck cares more about data-slide guidance than about academic delivery tips).
- Prefer principles that generalize (contrast, hierarchy, one-idea-per-slide, consistent grid) over site-specific stylistic opinions.
- If the user's own supplied reference URLs (from Step 2 of SKILL.md) conflict with these general design sources, prioritize the user's own material for *content*, and these sources for *design mechanics*.
- If none of these sites are reachable in the current environment (e.g. network restrictions), tell the user plainly and proceed using established design knowledge instead of silently skipping this step.
